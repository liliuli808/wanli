# “碗里” (WanLi) - 核心用户流程文档 (user-flows.md)

为了向 AI 编程助手和开发团队清晰展示用户与系统的交互轨迹，本项目核心业务流程通过以下 4 个核心状态转换与时序流程图进行定义。

---

## 一、 视频提交与 AI 结构化解析流程 (核心闭环 1)

该流程展示了用户粘贴 B 站链接后，系统从“去重校验”、“字幕检测”到“AI 结构化解析”和“人工校对发布”的完整状态机：

```text
  [ 粘贴 B 站链接 ]
         │
         ▼
  ┌────────────────────────┐
  │   1. 唯一 BVID 校验    ├─────────► [ 已存在 ] ──► 提示并直接跳转到已有菜谱页
  └──────────┬─────────────┘
             │ [ 未解析过 ]
             ▼
  ┌────────────────────────┐
  │ 2. 字幕拉取与强制校验  ├─────────► [ 无可用字幕/拉取失败 ] ──► 终止任务：显示“该视频没有可用字幕，无法解析”
  └──────────┬─────────────┘
             │ [ 获取到字幕；简介/评论可作为补充 ]
             ▼
  ┌────────────────────────┐
  │ 3. AI 结构化 Schema 解析│ ──► [ 解析失败/超时 ] ──► 记录故障码，允许提交者重试一次
  └──────────┬─────────────┘
             │ [ 解析成功 ]
             ▼
  ┌────────────────────────┐
  │  4. 提交者进入校对预览  │ ──► 提交者可在 App 内手动修正食材名、用量、步骤错漏
  └──────────┬─────────────┘
             │ [ 点击确认发布 ]
             ▼
  [ 写入数据库，对外公开为 v1 ]
```

## 二、 来源纠错与版本发布流程 (核心闭环 2)

“来源解析版”不允许被普通用户直接覆盖。如果社区用户发现 AI 解析出的配料用量或步骤有误（如与视频口播不符），须通过以下“纠错流程”进行修改：

```text
   社区用户甲 ──► 点击“来源纠错” ──► 复制当前正文副本 ──► 在副本上修改错漏
                                                               │
                                                               ▼
                                                     提交“纠错建议书” (带修改理由)
                                                               │
                                                               ▼
                                                     原发布者（提交视频的用户）
                                                     在 App 内收到待审核通知
                                                               │
                                         ┌─────────────────────┴─────────────────────┐
                                         ▼ [ 同意 ]                                  ▼ [ 拒绝 ]
                                 合入来源解析版，                                建议关闭
                             生成新版本 RecipeVersion                             通知用户甲
                         (如来源解析版 v1 -> v2)
```

## 三、 派生社区改编版流程 (核心闭环 3)

当用户想要改变菜谱本身的烹饪性质（例如：将“油炸红烧肉”改为“空气炸锅减脂版红烧肉”）时，应使用“派生改编”流程。**注意：改编不经过原作者审核，一经发布直接作为独立版本公开。**

```text
   任意登录用户 ──► 点击“派生改编” ──► 系统派生当前 RecipeVersion
                                                    │
                                                    ▼
                                          自由增删、替换调料与步骤
                                          (如：把糖换成代糖，烤箱换成空气炸锅)
                                                    │
                                                    ▼
                                          发布为“用户独立改编版”
                                          (页面强制标注：改编自 xxx 菜谱 v2 版)
                                                    │
                                                    ▼
                                    【可被其他用户继续改编，形成版本树】
                                    (只有“个人适配版”公开后才是终端节点，不可再改编)
```

## 四、 个人厨房智能适配流程 (核心闭环 4)

用户手动发起“智能适配”时，系统将读取“我的厨房”中调料、厨具、忌口偏好，重写该菜谱：

```text
    用户点击 “适配当前厨房”
               │
               ▼
    后端服务读取：
    - 我的厨房拥有调料（有/无）
    - 我的厨房拥有厨具
    - 我的个人忌口（过敏源、偏好不吃、口味偏好）
               │
               ▼
    安全过敏拦截校验：
    是否存在用户“过敏源/健康忌口”且 AI 无法安全替代的食材？
         ├──────────────────────────────────────────┐
         ▼ [是：存在严重过敏/无法替代食材]         ▼ [否：可安全替代或无冲突]
    直接强行拦截，提示“由于过敏源安全限制，            AI 进行配料重写与步骤适配：
    该菜谱无法安全制作”并终止。                        1. 标注缺少的必要调料/厨具
                                                    2. 替换忌口、缺失食材，解释变化
                                                    3. 重新输出分步步骤
                                                               │
                                                               ▼
                                                    生成“个人适配版”(默认私有)
                                                               │
                                             ┌─────────────────┴─────────────────┐
                                             ▼ [用户选择公开]                    ▼ [仅自用]
                                       公开分享到社区。                     保存在个人中心。
                                 【其他用户不可再改编此适配版】
```
