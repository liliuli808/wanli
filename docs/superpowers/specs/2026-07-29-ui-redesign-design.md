# 碗里 App UI 重设计（Stitch 清新自然系 + 社交化重构）

日期：2026-07-29
状态：已确认方向（范围/首页定位/品牌色均由用户在澄清问题中选定）

## 1. 背景与问题

现有 Android App（Jetpack Compose + M3）被用户评价为「太老旧」「社交属性太差」。代码走查定位的根因：

**视觉老旧**
- 全 App 用 emoji 充当图标（🧂👨‍🍳🍳📝🔒😵），无正式图标体系
- 首页是「B 站链接输入框 + 提交按钮」的工具表单，无内容气质
- 发现页卡片仅 84dp 小缩略图，美食 App 不靠图片驱动
- 厨房/忌口页为成排 FilterChip 表单，像管理后台
- 详情页底部一排满宽按钮堆叠（版本树/纠错/适配/派生）
- 系统默认字体，无品牌字体与层级对比

**社交属性弱**
- UGC（做过照片、评论、改编版本）全部埋在详情页底部 CommunitySection
- 无用户身份体系：作者仅一行 "by xxx" 文字，无头像/昵称/主页
- 版本树（产品最独特的社交资产）只是朴素列表
- 无互动反馈回路：无点赞、无显著「N 人做过」徽章、无消息中心

## 2. 已确认的范围决策

| 决策点 | 用户选择 |
|---|---|
| 重设计范围 | **B：视觉焕新 + 社交展示重构**（不动核心功能；允许少量后端补充：昵称/头像字段、聚合接口） |
| 首页定位 | **内容 Feed 为主，视频导入降为入口**（顶部搜索栏式导入 + 必要时 FAB） |
| 品牌色 | **推倒重来 → 清新自然系**：鼠尾草绿 `#5B7F5C` + 米白 `#FAF7F0` + 芥末黄点缀 `#D9A441` + 深墨绿文字 `#1F2B21`，日式 zakka 气质 |
| Stitch 项目 | 复用已有空项目「AI厨房助手」（projects/5192070956370414107） |
| 执行方式 | 方案 A：设计系统先行 → 逐屏生成 → 导出 HTML 作为 Compose 实现基准 |

## 3. 信息架构（5 Tab 重构）

| 位置 | 现状 | 改为 |
|---|---|---|
| Tab 1 | 首页（导入工具） | **首页 · Feed**：社区「做过」照片流 + 关注作者新版本动态；导入为顶部搜索栏式入口 |
| Tab 2 | 发现（文字列表） | **发现**：双列图片瀑布流，大卡封面 + 作者头像 + 「N 人做过」徽章；保留最新/最热/分类 |
| Tab 3 | 厨房 | **厨房**：功能不动，视觉重做（emoji→图标，chip 表单→网格卡片） |
| Tab 4 | 忌口 | **消息**：评论回复、纠错审核结果、有人 fork 了你的版本；忌口降级并入「我的 · 设置」 |
| Tab 5 | 我的 | **我的**：头像+昵称身份区、我的做过（照片墙）、我的版本、我的收藏、设置（含忌口） |

关键取舍：忌口是低频设置项，不配独占一级 Tab；消息 Tab 第一版用现有后端数据（评论、纠错状态）即可撑起。

## 4. 视觉语言（Stitch 设计系统 Token）

| Token | 取值 |
|---|---|
| 主色 | 鼠尾草绿 `#5B7F5C`（按钮、选中态、品牌） |
| 背景 | 米白 `#FAF7F0`；卡片纯白 `#FFFFFF` 浮起 |
| 点缀 | 芥末黄 `#D9A441`（评分星、「做过」徽章、收藏等社交高光） |
| 文字 | 主 `#1F2B21` / 次 `#6B7A6D` |
| 语义色 | 错误 `#B3402A`、成功 `#4A7A4F`、警告 `#C98A2D` |
| 圆角 | 12dp 基准（卡片 16dp，头像/徽章全圆） |
| 字体 | 标题衬线感 + 正文无衬线（Noto Serif / Noto Sans，中文回退系统字体），靠字重字号差拉开层级 |
| 图标 | 全面弃用 emoji，统一 Material Symbols Rounded 线性图标 |
| 图片 | 食物照片全宽大卡、1:1 做过照片墙、圆形作者头像 |

暗黑模式：本期不做，浅色先行（zakka 风格浅色最成立），后续迭代补充。

## 5. 社交展示改造（按界面）

**首页 Feed（全新）**
- 卡片主体 = 社区「做过」动态：全宽美食照片 + 作者头像/昵称 + ★ 评分 + 一句话反馈 + 所属菜谱入口；芥末黄「N 人做过」徽章
- 穿插「新版本」动态卡：「@某某 发布了《xxx》的空气炸锅改编版」+ 头像链归属（改编自 → 来源解析版 → UP 主）+「N 个改编版」徽章

**菜谱详情页**
- 「做过墙」横滑照片墙提升到评论区之前
- 版本谱系入口改为可视化芯片：`UP主原版 → 3个改编`，点击进入图形化版本树
- 评论区重做：头像 + 昵称 + 时间线样式

**版本树（重点重做）**
- 朴素列表 → 谱系树状图：根节点 UP 主原版，分支为各改编版，节点含作者头像与改编说明

**我的**
- 顶部身份区：头像 + 昵称 + 简介
- 「我的做过」照片墙，可分享

## 6. 后端小补充清单（范围 B 内）

1. 用户表加 `nickname` / `avatar_url` 字段 + 修改接口
2. 聚合接口：最近「做过」记录流（首页 Feed 用；现有接口仅支持按菜谱查询）
3. 消息列表接口（聚合：我的评论的回复、我的纠错审核结果）——第一版可先做简单版

## 7. Stitch 执行清单

1. `create_design_system`：「碗里 · 清新自然系」，按第 4 节 token
2. 按序生成屏幕（均应用设计系统）：首页 Feed → 发现 → 菜谱详情 → 版本树 → 厨房 → 消息 → 我的 → 次级屏（登录、适配我的厨房、校对/编辑、空状态/加载态）
3. 每 2-3 张检查方向，跑偏用 `edit_screens` 修正
4. 全部确认后导出 HTML，作为 Compose 实现的视觉基准

## 8. 非目标（本期不做）

- 点赞、关注关系、私信、个性化推荐（需较大后端工作，后续迭代）
- 暗黑模式
- 大字烹饪模式（docs 中已规划但未实现，与本次重设计独立）
- 后端接口实现（本设计只列需求清单，实现另行排期）
